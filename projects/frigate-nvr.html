Second site: Raspberry Pi 5 with a Hailo-8L

The Pi runs Frigate for a set of outdoor Reolink cameras. The Hailo-8L on the Pi's M.2 HAT does the object detection at about 10 ms per inference, which leaves the Pi's CPU free for video.

Getting the accelerator working meant matching the Hailo kernel driver exactly to the HailoRT version bundled in the Frigate image. The first attempt used the wrong one.

Alerts only for zones that matter

Cameras that can see the street turned every passerby into an alert. I drew zones in the Frigate UI around the areas I care about and made them required for alerts. People outside a zone are still recorded as detections, but they don't buzz my phone.

cameras:
  front:
    review:
      alerts:
        required_zones: [entry]   # outside this zone: detection, not alert

Keeping a headless box healthy

  • A root cron job runs a full upgrade every morning and reboots only when a newer kernel of the same flavor is installed.
  • The kernel packages are on hold, because the Hailo driver is built against one specific kernel. Kernel updates are a manual step: upgrade, rebuild the driver, reboot, check. I learned this the hard way.
  • Shutdown and halt are redirected to reboot, the hardware watchdog resets the Pi if systemd hangs for 15 seconds, and a kernel panic reboots after 10 seconds. The Pi has no screen or keyboard, so it has to recover on its own.
  • Caddy serves Frigate over HTTPS with its own private CA, given a unique name so it can't collide with the home server's. That mattered.
# poweroff and halt become reboot
sudo ln -sf /usr/lib/systemd/system/reboot.target /etc/systemd/system/poweroff.target
sudo ln -sf /usr/lib/systemd/system/reboot.target /etc/systemd/system/halt.target

# hardware watchdog and reboot on panic
sudo sed -i 's/^#\?RuntimeWatchdogSec=.*/RuntimeWatchdogSec=15s/' /etc/systemd/system.conf
echo 'kernel.panic = 10' | sudo tee /etc/sysctl.d/99-reboot-on-panic.conf

Home: OpenVINO on the home server

The second install watches my studio with a Tapo camera. There's no accelerator in this box, so detection runs on the Intel integrated GPU through OpenVINO, using a YOLOv9-tiny model at 320×320. I built the ONNX model myself with the export Dockerfile from Frigate's docs, after fixing a step that failed to fetch the source.

  • go2rtc keeps one connection to the camera and restreams it. Frigate records the main stream and detects on the substream.
  • Video decoding uses VAAPI on the iGPU, so the CPU stays mostly idle.
  • Motion masks cover the camera's timestamp overlay, which otherwise counts as motion every second.
  • Only people inside a doorway zone become alerts.
detectors:
  ov:
    type: openvino
    device: GPU

model:
  model_type: yolo-generic
  path: /config/model_cache/yolov9-t-320.onnx
  width: 320
  height: 320
  input_tensor: nchw
  input_dtype: float
  labelmap_path: /labelmap/coco-80.txt

ffmpeg:
  hwaccel_args: preset-vaapi

Ignoring myself

The camera covers my workspace, so I'm in frame all day. Frigate's face recognition is on, and when it recognizes me it adds my name as a sub-label. The notifier drops any alert carrying that sub-label.

Notifications

frigate-notify polls each Frigate's API every 15 seconds in reviews mode, so it only sees finished alerts, not every detection. It sends one push per alert to ntfy. Each site uses its own random topic name, which works like a password, and links back to Frigate over HTTPS so tapping a notification opens the clip.

app:
  mode: reviews
frigate:
  server: http://frigate:5000
  public_url: https://frigate.lan
  webapi:
    enabled: true
    interval: 15
alerts:
  general:
    notify_once: true
  labels:
    allow: [person]
  sublabels:
    block: [Frank]
  ntfy:
    enabled: true
    server: https://ntfy.sh
    topic: REPLACE-WITH-A-LONG-RANDOM-TOPIC
