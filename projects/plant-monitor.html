Plant monitor

A microcontroller in a plant pot that tells me when the soil is dry. It's the smallest device on my network, and it uses the same DNS, HTTPS and notification setup as everything else.

Board
ESP8266, programmed in the Arduino IDE
Sensor
Analog soil moisture probe on pin A0
Calibration
Raw 700 is dry, raw 300 is wet, below 40% means water it
Network
Static address, Pi-hole for DNS, HTTPS through Caddy on the home server
Alerts
ntfy push at 08:00, 12:00 and 20:00

How it works

  • On boot, it joins Wi-Fi with a fixed address, syncs the clock over NTP, and starts a web server on port 80.
  • Opening the page reads the sensor and returns the moisture percentage and whether the plant needs water.
  • Every five minutes, the loop takes a reading. When the hour matches one of the three alert times, it posts the reading to ntfy once.
  • The ESP8266 only speaks plain HTTP. Caddy on the home server puts HTTPS in front of it, like every other .lan name.
void handleRoot() {
  int raw = analogRead(A0);
  int percent = constrain(map(raw, DRY_VALUE, WET_VALUE, 0, 100), 0, 100);
  String status = (percent < THRESHOLD) ? "needs water" : "OK";
  server.send(200, "text/plain",
              "Moisture: " + String(percent) + "% (" + status + ")");
}

The bug: a web server that never started

After flashing, the board answered pings but refused HTTP connections. The serial monitor showed it connected to Wi-Fi and then went silent.

The cause was the NTP wait in setup(). It looped until the clock was set, and server.begin() came after it. If NTP was slow or blocked, the loop never ended and the server never started. Capping the wait at 20 tries (10 seconds) fixed it. The page now comes up even if time sync fails, and the scheduled alerts start working once the clock catches up.

configTime(-7 * 3600, 0, "pool.ntp.org", "time.nist.gov");
time_t now = time(nullptr);
int attempts = 0;
while (now < 100000 && attempts < 20) {   // was: wait forever
  delay(500);
  now = time(nullptr);
  attempts++;
}

server.on("/", handleRoot);
server.begin();

Notes

  • The ntfy request uses setInsecure(), which skips certificate checks to save memory on the ESP8266. That's acceptable for a plant reading. I'd pin the certificate for anything sensitive.
  • The Wi-Fi credentials and ntfy topic live in a secrets.h file that isn't committed. The repository has a template.
