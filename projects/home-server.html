Home server

One small-form-factor PC that runs my DNS, media, file sync, camera NVR and RHEL practice VMs. Every service has its own address on my LAN and its own HTTPS name, and none of it is exposed to the internet.

Storage
500 GB internal NVMe, 8 TB Seagate Barracuda in a USB enclosure
OS
Red Hat Enterprise Linux 10, registered with subscription-manager
Runtime
Docker CE with Compose, KVM and libvirt, Cockpit
Network
One NIC with a static address, Tailscale for remote access

How a request gets to a service

Decisions and tradeoffs

Each service gets its own LAN address

Pi-hole needs ports 53 and 80, and other devices on the LAN should be able to reach a service directly. A Docker macvlan network gives each container a real address on the LAN, so ports never collide and every service shows up like its own device.

The catch is that Linux won't let a host talk to its own macvlan children through the parent interface. I fixed that with a small macvlan interface on the host, the shim, that has a single /32 address and one /32 route per container. It's a NetworkManager connection, so it comes back after reboots.

# example addresses
# the network containers attach to
docker network create -d macvlan \
  --subnet 10.0.10.0/24 --gateway 10.0.10.1 \
  -o parent=eno1 macvlan_net

# the host-side shim, persistent through NetworkManager
sudo nmcli connection add type macvlan con-name macvlan-shim \
  ifname macvlan-shim macvlan.parent eno1 macvlan.mode bridge \
  ipv4.method manual ipv4.addresses 10.0.10.2/32
sudo nmcli connection modify macvlan-shim \
  +ipv4.routes "10.0.10.53/32" +ipv4.routes "10.0.10.80/32"
sudo nmcli connection up macvlan-shim

HTTPS on names that only exist on my LAN

Public certificates need a public domain and either an open port or a DNS API. I wanted neither for internal services, so Caddy runs its own certificate authority with tls internal, and Pi-hole resolves the .lan names. Each device trusts the root certificate once. To make that easy, Caddy also serves the root certificate as a download from a local address. Apps without their own login get Caddy's basic_auth in front of them.

https://jellyfin.lan {
    tls internal
    reverse_proxy 10.0.10.65:8096
}

http://ca.lan {
    handle /ca.crt {
        rewrite * /root.crt
        root * /data/caddy/pki/authorities/local
        header Content-Type application/x-x509-ca-cert
        file_server
    }
    respond 404
}

Config on the internal disk, bulk data on USB

At first, everything lived on the 8 TB USB drive, including Caddy's certificates. When the drive dropped off the bus, every site went down at once. I moved compose files and app state to /srv/docker on the internal NVMe, so only media, Seafile data and VM disks stay on the USB drive. The mount uses nofail so the server still boots if the drive is missing.

Remote access without opening ports

My ISP uses carrier-grade NAT, so port forwarding isn't an option anyway. Tailscale gives my laptop and phone a private path to the servers without exposing anything publicly.

RHEL specifics

  • Static addressing is a NetworkManager profile, managed with nmcli.
  • firewalld allows only the services in use.
  • VM disks on the external drive needed an SELinux label before libvirt could use them.
  • Docker CE comes from Docker's RHEL repository. Podman is on my list to learn next.
sudo semanage fcontext -a -t virt_image_t "/mnt/storage/vms(/.*)?"
sudo restorecon -Rv /mnt/storage/vms
sudo firewall-cmd --permanent --add-service={http,https}
sudo firewall-cmd --reload
